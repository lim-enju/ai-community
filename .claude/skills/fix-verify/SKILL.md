# 버그 수정 + 실제 검증

사용자가 버그/화면 이상을 보고하면 아래 순서를 지킨다. **유닛 테스트(헬퍼 함수)만 통과했다고 "고쳤다"고 말하지 않는다** — 그렇게 넘겼다가 실제로는 내용이 사라진 채 배포한 적이 있다.

## 1. 실제 데이터로 재현
- 합성 샘플로 넘겨짚지 말고, **라이브 응답을 직접 본다**. 백엔드가 있으면 `curl http://localhost:3000/...` 로 실제 JSON 확인.
- 대표 케이스의 분포를 센다(예: 단일 줄 글 vs 여러 줄 글, 빈 값, null). 버그는 보통 소수 케이스에서 난다.

## 2. 근본 원인 수정
- 증상이 아니라 원인 지점을 고친다. 여러 화면이 같은 모델/서비스를 쓰면 **공유 지점에서 한 번** 고친다.
- 데이터에 실제로 뭐가 들어오는지(필드 유무, 형태) 먼저 확인하고 고친다. 모델 `fromJson`의 유도 로직을 특히 조심.

## 3. 렌더 테스트 추가 (핵심)
- 헬퍼 로직 테스트로 끝내지 말고, **위젯을 실제로 렌더**해서 화면 출력을 assert한다.
- 실제 응답과 같은 shape로 데이터를 만든다: `Model.fromJson({...})` 사용(생성자 직접 호출보다 실제 경로에 가깝다).
- 대표 케이스를 **모두** 커버한다(단일/여러 줄, 빈 값 등). "내용이 화면에 보이는가"를 `find.textContaining(...)` 등으로 확인.

## 4. 검증
- `flutter test` / `npm run eval` 통과 확인.
- 백엔드가 떠 있으면 **실제 응답으로 한 번 더** 확인(가능하면 전체 데이터에 로직을 돌려 이상 케이스 수를 센다).
- `lib/` 를 고쳤으면 `flutter build web` 재빌드 후 :8080 재시작(서비스워커 캐시).

## 5. 보고
- 4번을 마치기 전엔 "고쳤다"고 하지 않는다. **무엇을, 어떤 데이터로 확인했는지** 함께 보고한다.
